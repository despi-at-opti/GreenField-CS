## Onboarding-to-Renewal Analysis — Implementation Plan

### Overview
New file `14_onboarding_renewal.sql` + HTML section. Analyzes Experimentation/Opal onboarding customers over a 2-year lookback from the `--quarter` param, joined to exec_deck renewal data.

### SQL: `queries/14_onboarding_renewal.sql` (2 queries)

**QUERY 1 — Scorecards + Histogram base** (global & by product/SKU):
- Filter to Experimentation + Opal product categories only
- Lookback: `--quarter` anchor minus 2 years (e.g. 2026-Q2 → go-lives from 2024-04-01 to 2026-06-30)
- Join: `ONBOARDING_CUSTOMERS.MCID = EXEC_DECK.MASTER_CUSTOMER_ID` + match on product
- Metrics: account count, mean TTGL L6M/L12M, median L6M/L12M, min, max, outlier count
- Histogram data: mean TTGL per COALESCE(product_code, product_sku)
- Same base filters as onboarding query 1 (Include_Element, REPORTING_CATEGORY, test accounts, Proposal BU=Onboarding)

**QUERY 2 — Detail table** (element-level):
- All columns from onboarding query 1 (MCID, Account Name, Engagement, Element, Region, Product Group, Product Code, Product SKU, Customer Status, Phase, ONB Status, Engagement Start, Kickoff, Go-Live, First Value, KOGT, KOGT_DELTA, TTGL, ARC_FILTER, is_outlier, product_category)
- Plus from exec_deck per MCID+product (joined via lateral/row_number): DATE_YM, ARR_RENEWAL, ARR_CHURN, renewal_rate = (ARR_RENEWAL + ARR_CHURN) / NULLIF(ARR_RENEWAL, 0)
- Multiple renewal rows per customer possible → use ROW_NUMBER to get cycle 1, cycle 2 chronologically, pivot into columns (or keep as separate rows — one row per element × renewal)

## Onboarding Metrics Rewrite — Implementation Plan

### Key Definitions (from PBI)

| Field | Source | SQL |
|-------|--------|-----|
| **Region** | `TERRITORY_C.NAME` (joined via Account) | `CASE WHEN CHARINDEX('-', t.NAME) > 0 THEN LEFT(t.NAME, CHARINDEX('-', t.NAME) - 1) ELSE t.NAME END` |
| **KOGT** | GO_LIVE_DATE - KICKOFF_DATE, floored at 0 | `GREATEST(DATEDIFF('day', KICKOFF_DATE_C, GO_LIVE_DATE_C), 0)` |
| **KOGT_DELTA** | KOGT minus L6M avg KOGT | `KOGT - AVG(KOGT) OVER (rows with GO_LIVE in L6M)` |
| **Engagement Start Date** | `dg.KIMBLE_ONE_EXPECTED_START_DATE_C` | direct column |
| **First Value Date** | `de.FIRST_VALUE_C` | direct column |
| **ARC Filter** | Was a WHERE exclusion → now a column | `ELEMENT_NAME NOT LIKE '%ARC%'` |
| **Active Customer** | STAGE + time entry recency | STAGE IN (...) AND `LAST_TIME_ENTRY_CHANGE_C >= -60 days` |

### SQL: 3 Queries (replacing current 8)

**QUERY 1 — Customer Detail** (element-level, NO ARC exclusion in WHERE):
- All 21 columns in order: MCID, Account Name, Engagement Name, Group ID, Element Name, Element ID, Region, Product Group, Product Code, Product SKU, Customer Status, Product Phase, Onboarding Status, Engagement Start Date, Kickoff Date, Go-Live Date, First Value Date, KOGT, KOGT_DELTA, TTGL_days, ARC_FILTER, is_outlier
- Territory join: `Account.TERRITORY_C → TERRITORY_C.ID` for region derivation
- is_outlier via window function (mean ± 1 stddev by product_category)

**QUERY 2 — KPI Scorecards** (via GROUPING SETS: global / region / product_group / product_category):
- Count Active Customers
- AVG Go-Live Time L6M, L12M
- Count Go-Lives L6M, L12M
- Mean / Median / Min / Max TTGL L6M, L12M
- Count Outliers L6M, L12M
- Standard PBI filters applied (including ARC)

**QUERY 3 — Monthly Trend** (last 12 months × region × product_group):
- go_live_month, region, product_group
- Mean TTGL, Median TTGL, Count

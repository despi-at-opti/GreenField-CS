## Context

The report has three interconnected data issues:

1. **`digital_arr_bands.sql` uses `INNER JOIN latest_account_arr`** — this drops 362 accounts that had renewal ARR at year-start but have since churned (no row in the latest ARR snapshot). It also creates a misleading "Unknown" bucket for 65 accounts with zero/null ARR in the latest snapshot.
2. **Section 6 (Population Overview)** is built from the main query's output (renewal/churn spine), so it only shows accounts with renewal events — not the full Digital CS book of business. This is why it showed 20 accounts in $100K-$200K when the real number is 97.
3. **No Named CS migration candidate view** — the stakeholder wants to see how many Named CS accounts in the $100K-$200K range would migrate if the ceiling were raised (answer: 685 accounts / $98.4M ARR). The report doesn't show this at all.

## Implementation Steps

### Step 1: Fix `digital_arr_bands.sql` — point-in-time ARR banding
- Replace the `latest_account_arr` CTE with a **point-in-time** CTE that joins ARR by MCID × month (similar to the approach in `01_base_product_group.sql`)
- Change `INNER JOIN` to `LEFT JOIN` so churned accounts are not dropped
- Band each account based on their ARR **at the time of the renewal/churn event**, not their current ARR
- This eliminates most of the "Unknown" bucket and includes all 362 dropped accounts

### Step 2: Run the corrected SQL and all data queries
- Execute the fixed SQL with `:target_quarter = '2026-Q3'`
- Run aggregation queries for each HTML data constant: `TREND_BAND`, `KPIs`, `DIM_DATA`, `DIM_SUMMARY`, `HEATMAP`, `CHURNERS`, `POP_OVERVIEW`, `EXP_ACCOUNTS`, `EXP_SUMMARY`, `PROD_MIX`, `SOL_TYPE_BAND`
- Run a new query for Named CS accounts in $100K-$200K (migration candidate pool) with renewal/retention metrics

### Step 3: Add "Named CS Migration Candidates" section to HTML
- New Section 6b (or restructure Section 6): "Named CS Accounts in $100K-$200K — Migration Candidate Pool"
- Bar charts: account count and total ARR by finer band ($100K-$150K, $150K-$200K)
- Table: breakdown by region, product solution, and current renewal performance
- This directly answers the stakeholder's question about the size/composition of the pool

### Step 4: Update Section 6 (Population) for full book of business
- Query the full Digital CS population from latest ARR snapshot (not just accounts with renewal events)
- Replace `POP_OVERVIEW` data with complete numbers

### Step 5: Update the HTML with corrected data
- Replace all embedded JSON constants with corrected data
- Add the new Named CS section HTML structure and JavaScript

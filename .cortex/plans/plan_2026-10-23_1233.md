## Implementation steps
1. **`sql/marts/fct_churn.sql`** (dynamic table): one row per renewal line item, keyed by `DATE_YQ`, so Product Solution (PS) and Core / Non-Core cuts add up.
   - **Amounts:** `BASELINE_ARR`, `CLOSED_WON_ARR`, `FULL_CHURN_ARR`, `DOWNGRADE_ARR`, `TOTAL_CHURN_ARR`, `FULL_LOGO_CHURN_ARR`, `OPEN_RENEWAL_ARR`.
   - **Full logo churn:**
     - `IS_FULL_LOGO_CHURN` = full churn on an account that is now an Ex-Customer, or full churn on a still-active account (approximation).
     - `LOGO_CHURN_BASIS` labels which of the two applies.
     - Logo counts = distinct accounts.
   - **Cuts, one column each:**
     - CS team at renewal, plus the current CS team.
     - CSM manager at renewal (historic), and CSM lead / portfolio from `portfolios.yml` (e.g. Line Wilkens-Lintrup's team).
     - Region (CDR, current).
     - PS (line), and Core / Non-Core (line: EO / EC / AI = Core).
     - Solution type: `SOLUTION_TYPE_OPP` (Single / Multi), with Non-Core when the opportunity has no Core line.
     - ARR band global and by CS team, at quarter start (`dim_account_qe`; NULL before 2024-Q3).
     - Segment, Clari node (opportunity CSM, live hierarchy).
   - **Reasons:** Salesforce loss reason, churn type and competitor. The AI reason columns are left NULL until the full AI run.
   - **Time:** `DATE_YQ`, `DATE_YQ_PRIOR_YEAR`, `LAST_ACTIVE_YQ`.

## Context

The migration Excel has 400 rows (392 unique accounts) with `Old Value` = the named CSM before migration to Digital. The SQL query's `churn` CTE currently only captures negative movements (Churn, Downgrade, Downsell, etc.). We need to expand it to also capture positive movements (Up Sell, Cross-sell) so we can answer: *Have these accounts upsold/cross-sold more or less since migration, per CSM?*

The movements table (`ADAPTIVE_MOVEMENTS_DATA`) has the upsell/cross-sell bridge types we need.

## Implementation Steps

### Step 1: Expand the SQL query (`digital_arr_bands.sql`)
- Rename `churn` CTE to `movements` (or add a parallel `growth` CTE)
- Add `Up Sell`, `Up Sell_swap`, `Up Sell - migration`, `Cross-sell`, `Cross-sell_swap`, `Cross-sell - migration` to the BRIDGE_ACCOUNT filter
- Add new columns: `UPSELL_ARR` and `CROSSSELL_ARR` (positive movements)
- Keep the existing churn columns unchanged so nothing breaks

### Step 2: Update `digital_arr_bands_analysis.py`
- Update `load_data()` to coerce the new `UPSELL_ARR` and `CROSSSELL_ARR` columns
- Update `load_migration_data()` to also return the CSM name (`Old Value` column)
- Update `enrich()` to merge the CSM name (`PREVIOUS_CSM`) onto the main dataframe
- Add new CSM-level aggregation functions:
  - `csm_migration_summary(df)` — per CSM: account count, migration months, total ARR before/after, upsell/cross-sell before/after, churn before/after
  - `csm_account_detail(df)` — per CSM × account: migration month, ARR before/after, upsell/cross-sell $ before/after, churn $ before/after
- Update `_agg()` to include UPSELL_ARR and CROSSSELL_ARR in standard aggregations

### Step 3: Update `digital_arr_bands_html.py`
- Add a new "CSM Migration Analysis" section to the HTML report with:
  - Summary table: one row per CSM showing accounts migrated, ARR before/after, upsell/cross-sell before/after, churn before/after
  - Drill-down: per-account detail within each CSM
